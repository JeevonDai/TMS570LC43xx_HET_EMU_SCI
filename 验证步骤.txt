=====================================
Clangd 配置验证步骤
=====================================

【重要】修复完成后，请按以下步骤验证：

步骤 1：重启 Clangd
-------------------
方法 A：
  1. 按 Ctrl+Shift+P
  2. 输入：clangd: Restart language server
  3. 按回车

方法 B：
  直接重启 VS Code

步骤 2：检查错误是否消失
-----------------------
打开以下文件并检查：
  - HALCoGen/include/HL_sys_common.h
  - HALCoGen/source/HL_esm.c
  - HALCoGen/source/HL_sys_pmm.c

预期结果：
  ✅ 错误数量应大幅减少（从几百个降到几个或零个）
  ✅ 不再出现 "Too many errors emitted"
  ✅ 不再出现 "Invalid argument '-std=c99' not allowed with 'Objective-C++'"

步骤 3：测试代码导航
-------------------
在 HALCoGen/source/HL_esm.c 中：
  1. 找到 #include "HL_esm.h"
  2. 按住 Ctrl 点击 "HL_esm.h"
  3. 应该能成功跳转到头文件

在任意函数调用处：
  1. 按住 Ctrl 点击函数名
  2. 应该能跳转到函数定义

步骤 4：测试代码补全
-------------------
在任意 .c 文件中：
  1. 输入 "esm" 然后按 Ctrl+空格
  2. 应该看到相关的函数和变量建议

步骤 5：查看 Clangd 日志（如果还有问题）
---------------------------------------
  1. VS Code -> View -> Output
  2. 在下拉菜单中选择 "Clang Language Server"
  3. 查看是否有错误信息

【如果问题仍然存在】
===================

问题 A："Invalid argument" 错误仍然出现
----------------------------------------
确认文件类型：
  - 在 VS Code 右下角应该显示 "C"
  - 如果显示 "C++" 或其他，点击它并选择 "C"

问题 B：找不到头文件
-------------------
检查编译器路径：
  打开 .clangd 文件，确认第 15 行路径存在：
  D:/ti/ccs1281/ccs/tools/compiler/ti-cgt-arm_20.2.7.LTS/include
  
  如果路径不同，请修改为正确的路径

问题 C：仍有大量错误
-------------------
尝试禁用 clangd，改用 C/C++ 扩展：
  1. 打开 .vscode/settings.json
  2. 找到 "C_Cpp.intelliSenseEngine": "disabled"
  3. 改为 "C_Cpp.intelliSenseEngine": "default"
  4. 保存并重启 VS Code

【修复的关键点】
===============
✅ 使用 -xc 强制 C 语言模式
✅ 添加 TI 编译器系统头文件路径
✅ 定义必要的 TI 编译器宏
✅ 移除可能导致冲突的 C++ 和 Objective-C++ 选项
✅ 在 VS Code 中将 .h 文件关联为 C 语言

【技术细节】
===========
- .h 文件默认可能被 clangd 识别为 C++、Objective-C 或 Objective-C++ 头文件
- -xc 选项强制将所有文件作为 C 语言处理
- -std=c99 与某些语言模式不兼容，已使用 -xc 替代
- TI 编译器使用特定的宏和内建函数，需要通过宏定义模拟
